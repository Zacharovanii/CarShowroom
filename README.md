# CarShowroom

Сайт автосалона: каталог с фильтрами, страница автомобиля с 3D-просмотром и выбором
цвета кузова, запись на тест-драйв, личный кабинет, обработка записей менеджером.

Учебный проект: практическая работа «Разработка многостраничного сайта на React
с маршрутизацией, регистрацией и авторизацией» (МДК 01.06), расширенная
собственным бэкендом и БД.

## Стек

| Слой | Технологии |
|---|---|
| Frontend | Vite, React 19, TypeScript, React Router (декларативный режим), TanStack Query, CSS Modules + дизайн-токены, React Three Fiber + drei |
| Backend | NestJS, postgres.js (SQL руками), Better Auth, zod |
| БД | PostgreSQL, миграции — SQL-файлы через dbmate |
| Контракт | `packages/contracts` — zod-схемы, общие для фронта и бэка |
| Монорепо | npm workspaces |

## Хранилище фото (MinIO)

Фото и 3D-модели, которые админ загружает в каталог, лежат в MinIO (S3) и отдаются API по
`/media/...` (D26). `npm run db:up` поднимает MinIO вместе с PostgreSQL, приватный
бакет `carshowroom` создаёт одноразовый сервис `minio-init`. Консоль —
http://localhost:9001 (`carshowroom` / `carshowroom123`).

API нужны переменные `S3_*` в `apps/api/.env`: на новом месте `.env` копируется из
`.env.example` целиком, а в уже существующий `.env` дописывается блок `S3_*` оттуда же.

## Почта: подтверждение email и сброс пароля

Регистрация требует подтверждения email, пароль восстанавливается письмом (D27). Письма
шлёт API через [Resend](https://resend.com). Переменные в `apps/api/.env` (шаблон —
`.env.example`):

| Переменная | Что это |
|---|---|
| `RESEND_API_KEY` | ключ API — в панели Resend, раздел API Keys |
| `MAIL_FROM` | отправитель: `CarShowroom <noreply@ваш-домен>` |

**В dev ключ не нужен.** Без `RESEND_API_KEY` письма не уходят: ссылка подтверждения
или сброса пароля пишется в лог API строкой `[Mail]` — открыть её в браузере, и сценарий
проходится целиком. Seed-учётки и менеджеры, созданные админом, уже подтверждены
и входят без писем. Если ключ в `.env` задан, dev-сервер шлёт настоящие письма; тесты
(`NODE_ENV=test`) — никогда, они читают письма из памяти процесса.

**В production** обе переменные обязательны, без них API не стартует; `MAIL_FROM`
обязателен и в dev, если задан ключ (иначе Resend отклонял бы каждое письмо). Тестовый
отправитель `onboarding@resend.dev` доставляет **только на адрес владельца аккаунта
Resend** — для реальных адресов нужен свой домен или поддомен: добавить его в Resend
(Domains) и прописать у регистратора выданные DNS-записи SPF и DKIM.

Ограничение частоты Better Auth (вход и регистрация 5 в минуту, письма 3 в минуту → 429)
считает по заголовку `X-Forwarded-For`, поэтому на сервере nginx перед API должен
перезаписывать его адресом клиента: `proxy_set_header X-Forwarded-For $remote_addr;`.

## Модели и фото автомобилей (обязательный шаг)

Настоящие 3D-модели и фото в репозиторий не входят (D25): модели лицензированы только
для некоммерческого использования, у фото лицензия не установлена. Без них сайт
работает, но вместо фото показывается «Фото не установлено», а в 3D — CC0-седан-заглушка.

1. Взять архив `licensed-assets` у владельца проекта. Откуда каждый файл —
   в [docs/assets-licenses.md](docs/assets-licenses.md); модели скачиваются с Sketchfab
   под своим аккаунтом.
2. Положить его в `apps/api/licensed-assets/` так, чтобы получилось:
   ```
   apps/api/licensed-assets/models/m4-competition.glb    (18 файлов, ~200 МБ)
   apps/api/licensed-assets/cars/m4-competition-1.jpg    (85 файлов)
   ```
   Имена файлов — `slug` автомобиля из `apps/api/db/seed/catalog.sql`.
3. Перезапускать ничего не нужно. Проверка: `/assets/models/m4-competition.glb` весит
   ~11 МБ (заглушка — 165 КБ), на `/catalog/m4-competition` видно настоящее фото.

На сервере — то же самое: каталог копируется рядом с `dist/` API при выкатке.
