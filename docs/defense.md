# Сценарий защиты

Демонстрация минут на десять: регистрация нового клиента → каталог → страница
автомобиля с 3D → запись на тест-драйв → кабинет → менеджер → админ → выход.
Для каждого шага сказано, что нажимать, что должно произойти и какое требование
ТЗ этим закрывается. Полная сверка с чек-листом — [assignment-check.md](assignment-check.md).

Общее правило демонстрации: **показывать адресную строку.** Половина требований ТЗ —
про маршрутизацию, и адрес доказывает их быстрее любых слов.

## 0. Что подготовить заранее

За 15 минут до защиты, по порядку:

```bash
npm install                     # если репозиторий свежий
npm run db:up                   # docker: cs-db на 5434, adminer на 8080, MinIO на 9000/9001
npm run build -w @carshowroom/contracts   # контракты нужны и API, и фронту
npm run db:migrate              # dbmate: схема
npm run db:seed                 # каталог (18 автомобилей) + три учётные записи
npm run dev:api                 # http://localhost:3000
npm run dev:web                 # http://localhost:5173
```

`apps/api/.env` — копия `apps/api/.env.example` (`cp apps/api/.env.example apps/api/.env`).
Без `WEB_ORIGIN=http://localhost:5173` Better Auth ответит 403 `INVALID_ORIGIN` на вход.
Фронту `.env` в dev не нужен: базовый URL по умолчанию `/api`, и Vite проксирует его
на API (`apps/web/.env.example` пригодится только для сборки под другой хост).

**Учётные записи из seed** (пароль у всех `password123`):

| Роль | Email |
| --- | --- |
| Клиент | `client@carshowroom.test` |
| Менеджер | `manager@carshowroom.test` |
| Админ | `admin@carshowroom.test` |

Чек-лист перед показом:

- [ ] База чистая: `select count(*) from test_drives;` → 0. Иначе демонстрация записи
      упрётся в «слот занят» или в лимит двух активных записей (TD-6).
      Очистить: `docker exec cs-db psql -U carshowroom -d carshowroom -c "delete from test_drives;"`
- [ ] Маршрут `/__ui` и `pages/UiKitPage.tsx` удалены — это служебная витрина кита,
      на защите она лишняя (см. «Осталось сделать» в assignment-check.md).
- [ ] `npm run typecheck`, `npm run lint`, `npm run build` — зелёные. Это же и ответ
      на вопрос про `var` и чистую консоль.
- [ ] Браузер: три вкладки (клиент, менеджер, админ) или один профиль и выход между ролями.
      Проще — **разные окна в режиме инкогнито**, тогда сессии не мешают друг другу.
- [ ] Консоль браузера открыта заранее и **пуста**. Это требование ТЗ, и показать её
      лучше самому, не дожидаясь вопроса.
- [ ] Email для регистрации придуман заранее и ещё не занят, телефон — строго `+7XXXXXXXXXX`.
- [ ] Письмо подтверждения (D27): без `RESEND_API_KEY` оно не уходит, ссылка — в
      терминале `npm run dev:api`, строка `[Mail]`; держать терминал под рукой. С ключом
      и тестовым отправителем `onboarding@resend.dev` письмо дойдёт только на ящик
      владельца аккаунта Resend — регистрироваться на него. Seed-учётки входят без писем.
- [ ] Интернет не нужен: шрифт лежит в репозитории, модели и фото — в
  `apps/api/licensed-assets/` (D25, шаг в README). Проверка:
  `/assets/models/m4-competition.glb` весит ~11 МБ, а не 165 КБ заглушки.

## Вероятные вопросы по коду

**Почему React Router в декларативном режиме, а не через `loader`?**
Данные везде идут через TanStack Query. Два механизма загрузки в одном проекте —
два места, где искать ошибку. Решение D3.

**Где Context API и почему он вообще нужен?**
`features/auth/authContext.ts` — текущий пользователь нужен шапке, guard-ам маршрутов,
блоку тест-драйва и кабинету, то есть на трёх разных уровнях дерева. Через пропсы
это были бы три цепочки проброса. Второй контекст — уведомления (`Toast`):
их показывает любая страница одной строкой `useToast()`.
Redux или Zustand не нужны: глобального клиентского состояния ровно два поля.

**Почему нет `useEffect` для синхронизации фильтров с URL?**
Потому что URL **и есть** состояние. `useSearchParams` читает, `setSearchParams`
пишет, лишнего прохода рендера нет. Эффект понадобился бы, только если бы существовала
вторая копия состояния — её нет.

**Где тогда `useEffect` есть?** Семь штук: блокировка прокрутки под мобильным меню,
Esc и клик мимо выпадающего меню, освобождение материалов three.js, сигнал «модель
готова», перекраска кузова при смене цвета, прокрутка ленты дней к выбранному,
задержка перед уходом поиска в URL. Все — про подписки и внешние системы,
то есть по назначению.

**Почему `useState` вызывается прямо в теле рендера в `Header.tsx:29`?**
Это приём из документации React: переход на другую страницу должен закрыть меню,
и правка состояния в рендере даёт React пересчитать компонент **до** отрисовки.
Эффект сделал бы это после — меню успело бы мигнуть поверх новой страницы.

**Почему деньги — строка?**
`numeric` в БД, строка в контракте, форматирование на фронте. Число с плавающей
точкой для денег — классическая ошибка: `0.1 + 0.2 !== 0.3`. Решение D12.

**Почему SQL руками, без ORM?**
Учебный проект, запросов немного, а ORM прячет то, что на защите как раз и спрашивают.
Исключение — Better Auth, у него свой пул внутри.

**Как устроена защита от двойной записи на один слот?**
Уникальный индекс `(car_id, starts_at)`. Нарушение `23505` переводится в `SLOT_TAKEN`
(409). Проверка `select`-ом заранее оставила бы окно между проверкой и вставкой.

**Сколько всего компонентов?** 88 функциональных при требуемых 8–10. Классовый один —
граница ошибок 3D-сцены: её на хуках не написать.

**Почему ключ по индексу в скелетонах?** Список заглушек неизменяемый, элементы
не переставляются и не удаляются. Во всех списках с данными ключ — `id` из базы.

**Как работает `prefers-reduced-motion`?** Длительности гасятся до 1ms прямо в токенах
плюс общее правило на `animation-duration` и `transition-duration`. Ни один компонент
не пишет длительность числом, поэтому обойти настройку негде. У 3D-сцены автовращения
нет — она движется только пока её крутит человек.

**Почему 3D грузится лениво?** Three.js — примерно мегабайт. Посетитель, который
не открыл вкладку «3D», не должен его качать. `React.lazy` + `Suspense`,
граница проходит по `CarScene.tsx`.

## Если что-то пойдёт не так

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Вход отвечает 403 `INVALID_ORIGIN` | не выставлен `WEB_ORIGIN` | поправить `apps/api/.env`, перезапустить API |
| «Слот занят» на демонстрации записи | в `test_drives` остались строки от репетиции | `delete from test_drives;` и обновить страницу |
| «Слишком много активных записей» | у клиента уже две будущие записи (TD-6) | отменить одну в кабинете |
| Каталог пустой | не применён seed | `npm run db:seed` |
| Вкладка «3D» не появилась | у этого автомобиля нет модели | взять тот, у которого в каталоге бейдж «3D» |
| Вместо фото «Фото не установлено», в 3D — серый седан | нет `apps/api/licensed-assets/` | положить каталог по README |
| Фото не грузятся | API не поднят: `/assets` раздаёт он | запустить `npm run dev:api` |
