# Сценарии использования

Сайт дилерского центра BMW (учебный проект; в подвале — пометка, что это не официальный
сайт BMW). Основной поток: **посмотреть каталог → открыть автомобиль → записаться
на тест-драйв**. Менеджер обрабатывает записи, админ заводит менеджеров и ведёт каталог.

Объём сознательно ограничен — см. «Чего в сервисе нет». Каталог наполняется seed-ом
и дальше ведётся админом: карточки, публикация, фото, 3D (UC-A3…UC-A6, D26).
Единица каталога — **автомобиль** с одной ценой (комплектаций нет).

---

## Объём сервиса

| Блок | Что входит |
| --- | --- |
| Каталог | список с поиском, фильтрами и сортировкой; страница автомобиля с фото, характеристиками и 3D |
| 3D | просмотр GLB-модели, вращение и приближение, смена цвета кузова из палитры автомобиля (только визуально, на цену не влияет) |
| Аккаунт | регистрация с подтверждением email, вход, выход, восстановление пароля письмом, контактные данные, смена пароля |
| Тест-драйв | выбор дня и слота, запись, свои записи, отмена будущей записи |
| Менеджер | список записей на день с фильтрами, смена статуса записи |
| Админ | список пользователей, создание менеджера; управление каталогом — карточки, публикация, фото, 3D (D26) |

### Чего в сервисе нет

Избранное, сохранённые конфигурации и расчёт цены конфигурации, комплектации и «цена от»,
доплата за цвет, календарь-сетка на неделю у менеджера, запись по звонку, блокировка
пользователей и смена ролей через интерфейс, настройки салона и праздники,
вход через соцсети (OAuth), редактирование справочников (серии, кузова, типы двигателя, цвета).

Всё это либо не нужно ни одному сценарию выше, либо стоит дороже, чем даёт (D18).

## Роли

| Роль                 | Кто это                       | Как появляется                           |
| -------------------- | ----------------------------- | ---------------------------------------- |
| Гость                | посетитель без входа          | —                                        |
| Клиент (`user`)      | зарегистрированный посетитель | самостоятельная регистрация              |
| Менеджер (`manager`) | сотрудник, ведёт тест-драйвы  | создаёт админ                            |
| Админ (`admin`)      | заводит менеджеров и ведёт каталог | в dev — seed; на сервере — скрипт `promote-admin.mjs` в контейнере API для зарегистрированного пользователя (D28, deploy.md §10); через интерфейс не назначается |

Права накопительные: **админ может всё, что менеджер.** Роль проверяет бэкенд
(guard на каждом эндпоинте), фронт лишь прячет недоступное.

Реализация — admin-плагин Better Auth: поле `role`, `listUsers`, `createUser`.

## Страницы

| Путь                   | Страница                                                  | Доступ                |
| ---------------------- | --------------------------------------------------------- | --------------------- |
| `/`                    | Главная — визитка салона                                  | все                   |
| `/catalog`             | Каталог: поиск и фильтры                                  | все                   |
| `/catalog/:slug`       | Автомобиль: фото/3D, характеристики, запись на тест-драйв | все (запись — клиент) |
| `/login`, `/register`  | Вход, регистрация                                         | только без входа      |
| `/forgot-password`     | Запрос письма для сброса пароля (UC-G8)                   | только без входа      |
| `/reset-password`      | Новый пароль по ссылке из письма, `?token=` (UC-G8)       | только без входа      |
| `/verify-email`        | Приёмник ссылки подтверждения, `?token=` (UC-G7)          | все                   |
| `/account`             | Кабинет, layout с `<Outlet />`                            | клиент                |
| `/account` (index)     | Контактные данные                                         | клиент                |
| `/account/test-drives` | Мои записи                                                | клиент                |
| `/manager`             | Записи на тест-драйв                                      | менеджер, админ       |
| `/admin/users`         | Пользователи                                              | админ                 |
| `/admin/cars`          | Автомобили: список с черновиками                          | админ                 |
| `/admin/cars/new`      | Новый автомобиль (черновик)                               | админ                 |
| `/admin/cars/:id`      | Карточка автомобиля: поля, фото, 3D, публикация           | админ                 |
| `*`                    | 404                                                       | все                   |

Навигация в шапке: «Главная», «Каталог» + по роли: «Записи» (менеджер, админ),
«Пользователи» и «Автомобили» (админ). Справа — «Войти / Регистрация» или имя
(→ кабинет) и «Выйти». После входа админ попадает на `/admin/users`.

## Правила тест-драйва

Живут константами в коде, в БД их нет: `apps/api/src/test-drives/rules.ts`; лимит TD-6
(`MAX_ACTIVE_TEST_DRIVES`) — в `packages/contracts`, его показывает и фронт.

| #     | Правило            | Значение                                                                | Почему                                                                 |
| ----- | ------------------ | ----------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| TD-1  | Длительность слота | **60 минут**                                                            | ~10 мин оформление, ~40 мин поездка, ~10 мин возврат; ровный час удобен |
| TD-2  | Часы               | начало слотов 10:00…18:00 → **9 слотов в день**, ежедневно              | салон работает 10–20, последний слот заканчивается до закрытия         |
| TD-3  | Часовой пояс       | один на весь проект — `Europe/Moscow`; в БД `timestamptz`               | салон один, второй пояс не нужен                                       |
| TD-4  | Ресурс             | один демо-автомобиль → **один слот автомобиля занимает одна запись**    | реальное ограничение: машина одна                                      |
| TD-5  | Горизонт записи    | от **через 2 часа** до **30 дней** вперёд                               | нужно время подготовить машину                                         |
| TD-6  | Лимит клиента      | не более **2 активных** будущих записей, не более одной на одно время   | защита от «забронировать всё»                                          |
| TD-7  | Отмена клиентом    | до начала слота                                                         | освобождает слот сразу                                                 |
| TD-8  | Условия            | при записи: телефон, отметка «права категории B», согласие на обработку ПДн | документы проверяются в салоне                                      |
| TD-9  | Статусы            | `scheduled` → `completed` / `no_show` (менеджер) или `cancelled` (клиент или менеджер) | менеджеру нужен результат визита, клиенту — история     |

## Гость

### UC-G1. Посмотреть главную

Визитка: hero с фото, коротко о салоне, несколько автомобилей из каталога, преимущества
(сервис, trade-in, кредит — текстом), контакты и адрес, кнопка «Записаться на тест-драйв»
→ каталог.

### UC-G2. Найти автомобиль в каталоге

1. Открывает `/catalog`, видит все опубликованные автомобили.
2. Ищет по названию, фильтрует: серия, кузов, тип двигателя, привод, цена от–до.
3. Сортирует: цена ↑↓, новизна.
4. Фильтры хранятся в URL — ссылкой можно поделиться, «назад» возвращает прежний выбор.

Альтернативы: ничего не найдено → пустое состояние и «Сбросить фильтры»; загрузка →
скелетоны; ошибка сети → сообщение и «Повторить».
Карточка: фото, название, год, цена, ключевые характеристики, бейджи «3D», «Электро».

### UC-G3. Изучить автомобиль

1. Открывает `/catalog/:slug`: название, цена, описание, характеристики.
2. Медиа: галерея фото; если есть 3D — вкладка «3D», модель грузится только при открытии
   вкладки (лоадер с прогрессом). Вращение, приближение, смена цвета кузова из палитры
   автомобиля — только визуально, цена не меняется.
3. Блок «Тест-драйв» с выбором дня и слота (UC-G4).

Альтернативы: slug не существует, автомобиль — черновик или снят с публикации →
«Автомобиль не найден» и ссылка в каталог; нет WebGL или модель не загрузилась → остаётся галерея.

### UC-G4. Посмотреть свободное время

1. Выбирает день (доступны дни от сегодня до +30 дней).
2. Сетка из 9 слотов: свободные активны, занятые и слишком близкие (TD-5) — нет.
3. Выбирает слот → «Записаться» → **переход на вход**; после входа возвращается на эту
   страницу с сохранёнными днём и слотом (`?date=&time=`) и продолжает UC-U3.

### UC-G5. Зарегистрироваться

Поля: имя, email, телефон, пароль, подтверждение, согласие на обработку ПДн. Проверки
на клиенте (та же zod-схема, что на бэке): не пустые, email, телефон в формате РФ,
пароль ≥ 8 символов, пароли совпадают, согласие отмечено.

1. «Зарегистрироваться» → аккаунт создан, **входа нет**: на адрес уходит письмо
   со ссылкой подтверждения (D27).
2. Форма сменяется экраном «Проверьте почту»: «Мы отправили письмо на {email}…
   Ссылка действует 1 час», кнопка «Отправить ещё раз» и внизу «Подтвердили email?
   Войти →». Письмо только что ушло, поэтому кнопка сразу на паузе 60 с — отсчёт
   строкой под ней: «Отправить снова можно через N с.»
3. Переход по ссылке из письма → UC-G7 → вошёл → `/account`.

Email занят: при обязательном подтверждении API отвечает тем же 200, что и для нового
адреса (иначе форма выдавала бы, кто зарегистрирован), — человек видит тот же экран
«Проверьте почту». Сообщение у поля «такой email уже зарегистрирован» предусмотрено
на случай, если подтверждение отключат.

### UC-G6. Войти

Email + пароль; под полем пароля, справа над кнопкой «Войти» — ссылка «Забыли пароль?»
→ `/forgot-password` (UC-G8). Неверные данные → общее сообщение «Неверный email или
пароль.» (без уточнения, что именно неверно). Успех → возврат или по роли:
клиент → `/account`, менеджер → `/manager`, админ → `/admin/users`.

Альтернативы:

- email не подтверждён (пароль верный) → 403 `EMAIL_NOT_VERIFIED`. Новое письмо API
  при такой попытке входа высылает само, поэтому над формой — предупреждение «Email не
  подтверждён. Мы отправили новое письмо на {email} — перейдите по ссылке из него.»
  и кнопка «Отправить письмо ещё раз», сразу на паузе 60 с (отсчёт строкой под ней);
- слишком частые попытки (5 в минуту) → 429, «Слишком много попыток, попробуйте
  через минуту.»

### UC-G7. Подтвердить email

1. Открывает ссылку из письма — `/verify-email?token=…` (страница фронта; она сама
   вызывает `GET /api/auth/verify-email`).
   Пока идёт запрос — «Подтверждаем email…» со спиннером.
2. Успех → адрес подтверждён, сессия создана → тост «Email подтверждён» и `/account`
   (переход — когда сессию увидел `AuthProvider`, иначе `ProtectedRoute` отправил бы
   на `/login`).

Альтернативы:

- ссылку открыли повторно (адрес уже подтверждён) → API отвечает тем же 200, но
  сессии не создаёт: гость видит «Email подтверждён. Теперь войдите с email и
  паролем.» и кнопку «Войти»; вошедший — уходит в кабинет, как при успехе;
- ссылка устарела (живёт 1 час) или недействительна → заголовок «Ссылка устарела» /
  «Ссылка недействительна», текст «Запросите новое письмо — укажите email, который
  вводили при регистрации.», поле email и «Выслать письмо заново»; внизу «Уже
  подтвердили email? Войти →»;
- повторная отправка («Отправить ещё раз» на экране «Проверьте почту», UC-G5,
  «Отправить письмо ещё раз» на входе, UC-G6, или форма выше) — ответ всегда
  успешный, даже для незнакомого адреса. Сообщение: «Письмо отправлено.», а в форме
  с полем email — «Если адрес зарегистрирован и ещё не подтверждён, мы отправили
  на него письмо.» После отправки кнопка 60 с недоступна, отсчёт — строкой под ней
  («Отправить снова можно через N с.»);
- слишком частые запросы (3 письма в минуту) → 429, «Слишком много попыток,
  попробуйте через минуту.»

Страница доступна всем — и гостю, и вошедшему: она не под `GuestOnlyRoute`, потому что
переход по ссылке выполняет вход и страница не должна пропасть посреди процесса.

### UC-G8. Восстановить пароль

1. «Забыли пароль?» на входе → `/forgot-password` («Восстановление пароля»): поле
   email → «Отправить ссылку».
2. Экран после отправки всегда один — «Проверьте почту»: «Если такой адрес
   зарегистрирован, мы отправили на него письмо со ссылкой для сброса пароля. Ссылка
   действует 1 час.» Есть ли такой пользователь, по ответу узнать нельзя.
3. Ссылка из письма → `/reset-password?token=…` («Новый пароль»): новый пароль +
   подтверждение (≥ 8 символов, совпадают) → «Сохранить пароль» → пароль сменён,
   **все сессии пользователя закрыты** → экран «Пароль изменён. Войдите с новым
   паролем.» и кнопка «Войти» (→ `/login`).

Альтернативы: ссылка без токена, устарела (1 час), уже использована или недействительна
(API их не различает — 400 `INVALID_TOKEN`; выясняется при отправке формы) → «Ссылка
недействительна» и кнопка «Запросить новую» → `/forgot-password`; слишком частые
запросы (3 письма в минуту) → 429, «Слишком много попыток, попробуйте через минуту.»
На обеих страницах внизу — «← Вернуться ко входу».

Обе страницы — только без входа. Вошедший меняет пароль в кабинете (UC-U2).

## Клиент

### UC-U1. Выйти

Сессия удаляется на сервере, шапка возвращается в гостевой вид, переход на главную.
Сессия переживает F5 и закрытие вкладки до истечения срока.

### UC-U2. Управлять контактными данными

`/account`: имя, email (только чтение), телефон, дата регистрации.
Редактирование имени и телефона; смена пароля (текущий + новый + подтверждение).

### UC-U3. Записаться на тест-драйв

1. На странице автомобиля выбирает день и слот.
2. Подтверждение в модалке: автомобиль, дата и время, телефон (подставлен из профиля,
   можно исправить), комментарий, отметки TD-8.
3. «Подтвердить» → запись `scheduled`, уведомление об успехе, ссылка «Мои записи».

Альтернативы:

- слот успели занять → 409 `SLOT_TAKEN`, сообщение «Время уже занято», сетка обновляется;
- превышен лимит TD-6 → сообщение со ссылкой на «Мои записи»;
- слот стал слишком близким (TD-5) → сообщение, сетка обновляется.

### UC-U4. Посмотреть и отменить свои записи

`/account/test-drives`: вкладки «Предстоящие» и «История».
Запись: автомобиль (ссылка), дата и время, статус, комментарий, причина отмены
(если отменил менеджер). Отмена предстоящей → диалог подтверждения → `cancelled`,
слот освобождается.

## Менеджер

### UC-M1. Смотреть записи

`/manager`: список записей на выбранный день — время, автомобиль, имя и телефон клиента,
статус. Навигация «Сегодня» / предыдущий / следующий день, выбор даты.
Фильтры: автомобиль и статус. Прошедшие записи со статусом `scheduled` подсвечены —
ждут отметки результата.

### UC-M2. Сменить статус записи

Клик по записи → панель: клиент (имя, телефон, email), автомобиль, время, комментарий,
когда создана. Действия:

- после начала слота: «Состоялся» (`completed`) / «Не пришёл» (`no_show`);
- до начала: «Отменить» с обязательной причиной (`cancelled`) — клиент видит причину.

Статус меняется один раз: закрытая запись не редактируется.
Записывают клиентов только сами клиенты через сайт. Сотрудники на тест-драйвы
не записываются, `/account/test-drives` им не показывается.

## Админ

### UC-A1. Просматривать пользователей

`/admin/users`: таблица — имя, email, телефон, роль, дата регистрации. Поиск по имени
и email, фильтр по роли, пагинация.

### UC-A2. Создать менеджера

Форма: имя, email, телефон, временный пароль → пользователь с ролью `manager`.
Пароль админ передаёт сотруднику сам (письмо менеджеру не отправляется). Email менеджера сразу
считается подтверждённым — за адрес ручается админ (D27).

Ограничение: роль `admin` через интерфейс не назначается.

### UC-A3. Управлять карточкой автомобиля

1. `/admin/cars`: таблица — обложка, название, серия, год, цена, бейджи «Черновик» /
   «Опубликован» и «3D». Поиск по названию и slug, фильтр статуса (все / опубликованные /
   черновики), пагинация — как у пользователей.
2. «Добавить автомобиль» → `/admin/cars/new`: название, slug, серия, кузов, тип двигателя,
   привод, год, описание, мощность, разгон, макс. скорость, цена, палитра — выбор из
   существующих цветов. «Создать» → черновик → переход на `/admin/cars/:id`.
3. `/admin/cars/:id`: те же поля и палитра (редактируются), фото (UC-A5), 3D (UC-A6),
   публикация (UC-A4), удаление.
4. «Удалить» → диалог подтверждения → автомобиль удаляется вместе с фото и моделью,
   переход в список.

Альтернативы:

- slug или название заняты → 409 `SLUG_TAKEN` / `NAME_TAKEN`, сообщение у поля;
- поле не прошло проверку → 400 `VALIDATION_FAILED`, сообщения у полей;
- у автомобиля есть записи на тест-драйв (любой статус) → 409 `CAR_HAS_TEST_DRIVES`,
  диалог «Удалить нельзя» с кнопкой «Снять с публикации» (UC-A4):
  записи — история клиента и менеджера, терять её нельзя;
- автомобиль не найден → 404 «Автомобиль не найден» и ссылка в список.

Смена slug у опубликованного автомобиля ломает старые ссылки — это на совести админа.
Seed-автомобили редактируются как любые другие. Справочники (серии, кузова, типы
двигателя, цвета) не редактируются — только выбор из существующих значений: их id
попадают в ссылки фильтров (D19), а ошибка в справочнике ломает весь каталог.

### UC-A4. Публиковать и снимать с публикации

1. В карточке — статус и кнопка «Опубликовать» (у черновика) или «Снять с публикации».
2. Опубликованный автомобиль появляется в каталоге; снятый пропадает.

Гость у черновика и снятого видит то же, что у несуществующего: `/catalog/:slug` →
404 «Автомобиль не найден» (UC-G3), в каталоге и на главной его нет, слоты и запись → 404.
Существующие записи остаются у клиента и менеджера и обрабатываются как обычно,
новые невозможны. Повторное нажатие ничего не меняет.

Альтернатива: у автомобиля нет ни одного фото → 409 `CAR_NOT_READY`, сообщение
«Добавьте хотя бы одно фото» — в каталоге карточка без обложки.

### UC-A5. Управлять фото

1. «Добавить фото» → обязательный alt (по умолчанию — название автомобиля) и выбор
   одного или нескольких файлов; alt получают все файлы пачки, у каждого фото его можно
   поправить потом. Файлы загружаются по очереди и встают в конец галереи.
2. У фото: изменить alt, «Заменить файл» (позиция и alt сохраняются), «Выше» / «Ниже»,
   «Удалить» с подтверждением. Первое фото — обложка в каталоге.

Альтернативы:

- не JPEG/PNG/WebP/AVIF (проверка по содержимому, не по расширению) → 400 `INVALID_FILE`;
- больше 10 МБ → 413 `FILE_TOO_LARGE`;
- в пачке файл с ошибкой отмечается сообщением, остальные загружаются;
- удаление последнего фото опубликованного автомобиля → 409 `LAST_IMAGE`, сначала
  снять с публикации. У черновика можно удалить и последнее.

### UC-A6. Управлять 3D-моделью

1. «Загрузить модель» (или «Заменить») → GLB-файл и поле «материал краски»
   (по умолчанию `CarPaint`) — по нему 3D-просмотр перекрашивает кузов.
2. После загрузки у автомобиля бейдж «3D», на странице автомобиля — вкладка «3D».
3. «Удалить модель» → подтверждение → вкладка «3D» пропадает, остаётся галерея.

Альтернативы:

- не GLB 2.0 → 400 `INVALID_FILE`; больше 60 МБ → 413 `FILE_TOO_LARGE`;
- материала с таким именем в модели нет → 400 `PAINT_MATERIAL_NOT_FOUND`, у поля
  список имён материалов из файла — выбрать нужное и загрузить снова.

## Сквозные требования

- Даты и время показываются в часовом поясе салона (`Europe/Moscow`) с явной подписью.
- Персональные данные клиентов (телефон, email) доступны только менеджеру и админу.
- Закрытие записи хранит, кто и когда это сделал (`closed_by`, `closed_at`);
  полноценного аудит-лога нет.
- Пустые состояния, скелетоны и ошибки — на каждой странице с данными.
- Адаптив: список записей менеджера, таблицы пользователей и автомобилей на телефоне — карточки.
