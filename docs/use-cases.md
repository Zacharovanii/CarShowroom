# Сценарии использования

Сайт дилерского центра BMW (учебный проект; в подвале — пометка, что это не официальный
сайт BMW). Основной поток: **посмотреть каталог → открыть автомобиль → записаться
на тест-драйв**. Менеджер обрабатывает записи, админ заводит менеджеров.

Статус: **согласовано, версия 2** (19.09.2026) — объём сознательно урезан, см. «Чего в сервисе нет».
Каталог фиксированный, наполняется seed-ом; управления каталогом в интерфейсе нет.
Единица каталога — **автомобиль** с одной ценой (комплектаций нет).

---

## Объём сервиса

| Блок | Что входит |
| --- | --- |
| Каталог | список с поиском, фильтрами и сортировкой; страница автомобиля с фото, характеристиками и 3D |
| 3D | просмотр GLB-модели, вращение и приближение, смена цвета кузова из палитры автомобиля (только визуально, на цену не влияет) |
| Аккаунт | регистрация, вход, выход, контактные данные, смена пароля |
| Тест-драйв | выбор дня и слота, запись, свои записи, отмена будущей записи |
| Менеджер | список записей на день с фильтрами, смена статуса записи |
| Админ | список пользователей, создание менеджера |

### Чего в сервисе нет

Избранное, сохранённые конфигурации и расчёт цены конфигурации, комплектации и «цена от»,
доплата за цвет, календарь-сетка на неделю у менеджера, запись по звонку, блокировка
пользователей и смена ролей через интерфейс, настройки салона и праздники,
подтверждение email, восстановление пароля письмом, админка каталога.

Всё это либо не нужно ни одному сценарию выше, либо стоит дороже, чем даёт.
Решение об упрощении — 19.09.2026.

## Роли

| Роль                 | Кто это                       | Как появляется                           |
| -------------------- | ----------------------------- | ---------------------------------------- |
| Гость                | посетитель без входа          | —                                        |
| Клиент (`user`)      | зарегистрированный посетитель | самостоятельная регистрация              |
| Менеджер (`manager`) | сотрудник, ведёт тест-драйвы  | создаёт админ                            |
| Админ (`admin`)      | заводит менеджеров            | seed-скрипт, через интерфейс не создаётся |

Права накопительные: **админ может всё, что менеджер.** Роль проверяет бэкенд
(guard на каждом эндпоинте), фронт лишь прячет недоступное.

Реализация — admin-плагин Better Auth: поле `role`, `listUsers`, `createUser`.

## Страницы

| Путь                   | Страница                                                  | Доступ                |
| ---------------------- | --------------------------------------------------------- | --------------------- |
| `/`                    | Главная — визитка салона                                  | все                   |
| `/catalog`             | Каталог: поиск и фильтры                                  | все                   |
| `/catalog/:slug`       | Автомобиль: фото/3D, характеристики, запись на тест-драйв | все (запись — клиент) |
| `/login`, `/register`  | Вход, регистрация                                         | только без входа      |
| `/account`             | Кабинет, layout с `<Outlet />`                            | клиент                |
| `/account` (index)     | Контактные данные                                         | клиент                |
| `/account/test-drives` | Мои записи                                                | клиент                |
| `/manager`             | Записи на тест-драйв                                      | менеджер, админ       |
| `/admin/users`         | Пользователи                                              | админ                 |
| `*`                    | 404                                                       | все                   |

Навигация в шапке: «Главная», «Каталог» + по роли: «Записи» (менеджер, админ),
«Пользователи» (админ). Справа — «Войти / Регистрация» или имя (→ кабинет) и «Выйти».

## Правила тест-драйва

Живут константами в API (`apps/api/src/test-drives`), в БД их нет.

| #     | Правило            | Значение                                                                | Почему                                                                 |
| ----- | ------------------ | ----------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| TD-1  | Длительность слота | **60 минут**                                                            | ~10 мин оформление, ~40 мин поездка, ~10 мин возврат; ровный час удобен |
| TD-2  | Часы               | начало слотов 10:00…18:00 → **9 слотов в день**, ежедневно              | салон работает 10–20, последний слот заканчивается до закрытия         |
| TD-3  | Часовой пояс       | один на весь проект — `Europe/Moscow`; в БД `timestamptz`               | учебный проект, второго пояса не будет                                 |
| TD-4  | Ресурс             | один демо-автомобиль → **один слот автомобиля занимает одна запись**    | реальное ограничение: машина одна                                      |
| TD-5  | Горизонт записи    | от **через 2 часа** до **30 дней** вперёд                               | нужно время подготовить машину                                         |
| TD-6  | Лимит клиента      | не более **2 активных** будущих записей, не более одной на одно время   | защита от «забронировать всё»                                          |
| TD-7  | Отмена клиентом    | до начала слота                                                         | освобождает слот сразу                                                 |
| TD-8  | Условия            | при записи: телефон, отметка «права категории B», согласие на обработку ПДн | документы проверяются в салоне                                      |
| TD-9  | Статусы            | `scheduled` → `completed` / `no_show` (менеджер) или `cancelled` (клиент или менеджер) | менеджеру нужен результат визита, клиенту — история     |

## Гость

### UC-G1. Посмотреть главную

Визитка: hero с фото, коротко о салоне, несколько автомобилей из каталога, преимущества
(сервис, trade-in, кредит — текстом), контакты и адрес, кнопка «Записаться на тест-драйв»
→ каталог.

### UC-G2. Найти автомобиль в каталоге

1. Открывает `/catalog`, видит все опубликованные автомобили.
2. Ищет по названию, фильтрует: серия, кузов, тип двигателя, привод, цена от–до.
3. Сортирует: цена ↑↓, новизна.
4. Фильтры хранятся в URL — ссылкой можно поделиться, «назад» возвращает прежний выбор.

Альтернативы: ничего не найдено → пустое состояние и «Сбросить фильтры»; загрузка →
скелетоны; ошибка сети → сообщение и «Повторить».
Карточка: фото, название, год, цена, ключевые характеристики, бейджи «3D», «Электро».

### UC-G3. Изучить автомобиль

1. Открывает `/catalog/:slug`: название, цена, описание, характеристики.
2. Медиа: галерея фото; если есть 3D — вкладка «3D», модель грузится только при открытии
   вкладки (лоадер с прогрессом). Вращение, приближение, смена цвета кузова из палитры
   автомобиля — только визуально, цена не меняется.
3. Блок «Тест-драйв» с выбором дня и слота (UC-G4).

Альтернативы: slug не существует или автомобиль снят с публикации → «Автомобиль не найден»
и ссылка в каталог; нет WebGL или модель не загрузилась → остаётся галерея.

### UC-G4. Посмотреть свободное время

1. Выбирает день (доступны дни от сегодня до +30 дней).
2. Сетка из 9 слотов: свободные активны, занятые и слишком близкие (TD-5) — нет.
3. Выбирает слот → «Записаться» → **переход на вход**; после входа возвращается на эту
   страницу с сохранёнными днём и слотом (`?date=&time=`) и продолжает UC-U3.

### UC-G5. Зарегистрироваться

Поля: имя, email, телефон, пароль, подтверждение. Проверки на клиенте (та же zod-схема,
что на бэке): не пустые, email, телефон в формате РФ, пароль ≥ 8 символов, пароли совпадают.
Успех → автоматический вход → возврат туда, откуда пришёл, иначе `/account`.
Ошибка: email занят → сообщение у поля.

### UC-G6. Войти

Email + пароль. Неверные данные → общее сообщение (без уточнения, что именно неверно).
Успех → возврат или по роли: клиент → `/account`, менеджер → `/manager`, админ → `/admin/users`.

## Клиент

### UC-U1. Выйти

Сессия удаляется на сервере, шапка возвращается в гостевой вид, переход на главную.
Сессия переживает F5 и закрытие вкладки до истечения срока.

### UC-U2. Управлять контактными данными

`/account`: имя, email (только чтение), телефон, дата регистрации.
Редактирование имени и телефона; смена пароля (текущий + новый + подтверждение).

### UC-U3. Записаться на тест-драйв

1. На странице автомобиля выбирает день и слот.
2. Подтверждение в модалке: автомобиль, дата и время, телефон (подставлен из профиля,
   можно исправить), комментарий, отметки TD-8.
3. «Подтвердить» → запись `scheduled`, уведомление об успехе, ссылка «Мои записи».

Альтернативы:

- слот успели занять → 409 `SLOT_TAKEN`, сообщение «Время уже занято», сетка обновляется;
- превышен лимит TD-6 → сообщение со ссылкой на «Мои записи»;
- слот стал слишком близким (TD-5) → сообщение, сетка обновляется.

### UC-U4. Посмотреть и отменить свои записи

`/account/test-drives`: вкладки «Предстоящие» и «История».
Запись: автомобиль (ссылка), дата и время, статус, комментарий, причина отмены
(если отменил менеджер). Отмена предстоящей → диалог подтверждения → `cancelled`,
слот освобождается.

## Менеджер

### UC-M1. Смотреть записи

`/manager`: список записей на выбранный день — время, автомобиль, имя и телефон клиента,
статус. Навигация «Сегодня» / предыдущий / следующий день, выбор даты.
Фильтры: автомобиль и статус. Прошедшие записи со статусом `scheduled` подсвечены —
ждут отметки результата.

### UC-M2. Сменить статус записи

Клик по записи → панель: клиент (имя, телефон, email), автомобиль, время, комментарий,
когда создана. Действия:

- после начала слота: «Состоялся» (`completed`) / «Не пришёл» (`no_show`);
- до начала: «Отменить» с обязательной причиной (`cancelled`) — клиент видит причину.

Статус меняется один раз: закрытая запись не редактируется.
Записывают клиентов только сами клиенты через сайт. Сотрудники на тест-драйвы
не записываются, `/account/test-drives` им не показывается.

---

## Админ

### UC-A1. Просматривать пользователей

`/admin/users`: таблица — имя, email, телефон, роль, дата регистрации. Поиск по имени
и email, фильтр по роли, пагинация.

### UC-A2. Создать менеджера

Форма: имя, email, телефон, временный пароль → пользователь с ролью `manager`.
Пароль админ передаёт сотруднику сам (письма не отправляем).

Ограничение: роль `admin` через интерфейс не назначается.

---

## Сквозные требования

- Даты и время показываются в часовом поясе салона (`Europe/Moscow`) с явной подписью.
- Персональные данные клиентов (телефон, email) доступны только менеджеру и админу.
- Закрытие записи хранит, кто и когда это сделал (`closed_by`, `closed_at`);
  полноценного аудит-лога нет.
- Пустые состояния, скелетоны и ошибки — на каждой странице с данными.
- Адаптив: список записей менеджера и таблица пользователей на телефоне — карточки.
