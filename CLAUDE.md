# CarShowroom

Учебный проект — сайт автосалона. Монорепо: `apps/web` (Vite + React), `apps/api` (NestJS),
`packages/contracts` (zod-схемы API). Решения — [docs/decisions.md](docs/decisions.md),
проектирование — [docs/design-plan.md](docs/design-plan.md).

## Инварианты

- **SQL пишется руками** через postgres.js. ORM и query builder не добавлять.
  Исключение — Better Auth, у него свой `pg` Pool внутри модуля `auth`.
- **Схема БД меняется только миграциями** (`apps/api/db/migrations`, dbmate, чистый SQL).
- **Контракт API — только `packages/contracts`.** Типы запросов/ответов не объявляются
  отдельно в `apps/web` или `apps/api`. Контракт описывает JSON как он есть на проводе
  (даты и деньги — строки).
- **Деньги:** `numeric` в БД, строка в контракте, на фронте только форматирование строки.
  У автомобиля одна цена, конфигуратора и расчёта итогов нет (D18).
- **Стили — CSS Modules + токены** из `apps/web/src/styles/tokens.css`. Хардкод цветов,
  отступов, радиусов и длительностей в модулях не допускается — только `var(--...)`.
- **Без React Server Components** и без SSR: фронт — SPA.
- **Демо-данные лежат в гите.** Проект учебный: seed БД, 3D-модели (`.glb`) и фотографии
  автомобилей хранятся в репозитории, а не во внешнем хранилище. Клонировал, поднял
  docker, применил миграции и seed — получил работающий сайт с контентом.
- **Не усложнять.** Конфиги, флаги, слои абстракции и зависимости добавляются только
  тогда, когда без них не обойтись, а не «на будущее».
